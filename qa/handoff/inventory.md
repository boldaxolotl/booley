# Inventory and supplemental check allocation

This planning catalogue accounts for the 62 capabilities in the
[shipped surface inventory](../../docs/research/qa-surface-inventory-20260902.md).
The existing journey catalogues retain their hardware checks; this catalogue
allocates public-contract checks that cannot be inferred from a successful
hardware journey. These are specifications, not execution evidence.

The [portfolio decision](https://github.com/boldaxolotl/booley/issues/254)
requires all supported obligations. The later
[host administration decision](https://github.com/boldaxolotl/booley/issues/252)
controls release identity, platform gates, owned-state cleanup, and licensing.
Every source column below refers to the named row of the inventory and its
linked public contract; implementation must retain those public links on checks.

## Encoding and independent outcomes

IDs below are complete when formed as `<scenario>.inventory.<capability>.<suffix>`;
display aliases map exactly to `picorv32-published-demo-continuity`,
`taxi-10g-mac-port-evolution`, and `opentitan-uart-clean-room-greenfield`.
All fully qualified IDs use those accepted long scenario IDs; short names below
are display aliases only. Each backticked suffix is a
**separate proposed check**, with the immediately following stimulus and oracle.
They must not be collapsed into one boolean for the row. A journey check may
replace a supplemental ID only through an explicit equivalence mapping preserving
that individual stimulus, oracle, capture point, and evidence. Existing IDs win
when the same observation already has a journey ID; these IDs name otherwise
unmapped obligations, not duplicate mandatory executions.

Evidence lives at `evidence/<check-id>/` and is captured immediately after the
stimulus, before restoration, retry, cleanup, or source inspection. Every command
probe retains argv with secrets omitted, exit code, stdout/stderr, public help
used, and exact Project/runtime/Target identity. The additional evidence named in
each row is mandatory; command exit zero alone is never a Flow or state oracle.
Expected controlled rejection passes its negative check only if the specified
failure class and unchanged protected state are both observed. Restore only the
run-owned fault, then execute the separately named recovery check. An unexpected
failure remains recorded even when recovery passes. Failure/recovery combinations
below are independent assertions, not alternatives.

All mutable fixtures are disposable, ledgered, and removed by the scenario cleanup
checks; retain their evidence first. Credentials use a disposable configuration
root, never the maintainer's credential store. Hooks, malformed inputs, synthetic
Targets and supervision probes belong to companion fixtures or disposable
branches, not unapproved edits to upstream RTL/TB. No live provider fault or paid
seat is manufactured. Controlled failure fixtures use public entry points; a
missing safe way to induce a required outcome remains an implementation gap,
not permission to invoke private internals or infer a pass.
