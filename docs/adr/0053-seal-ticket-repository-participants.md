# Seal Ticket repository participants and publish them with a journal

Target authoring now happens on Ticket-owned branches created with the draft, while Project destination branches remain valid and Doctor-clean. Target Contract schema 3 seals each outer and optional project-data participant's Ticket ref, destination ref, and commit identities; execution worktrees are disposable projections of those durable refs. Acceptance prepares every repository candidate before publication, publishes the project-data repository before the outer repository, and records roll-forward progress in an Acceptance Journal because Git cannot atomically update two repositories. The journal freezes the effective cleanup policy and extends through project-data and outer Ticket-ref retirement. Cleanup removes a ref only when it still has the sealed identity, treats an already-absent ref or worktree as complete, and leaves moved refs or dirty worktrees intact for inspection and retry. The completion plan rejects cleanup when any Ticket ref is also its destination ref. Acceptance is serialized Board-wide while any journal still has repository publication pending; after every destination lands, the Ticket is done even if its journal reports cleanup pending. Schema 3 is the only supported contract format; older Tickets must be recreated. Schema-3 Tickets do not use integration branches as intermediate destinations and reject retired `integration_base` metadata.
