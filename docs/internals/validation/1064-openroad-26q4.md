# OpenROAD 26Q4 validation

Validated on 03 OCT 2026 for [issue #1064](https://github.com/boldaxolotl/booley/issues/1064).

## Provenance and script compatibility

The upstream [26Q4 annotated tag](https://github.com/The-OpenROAD-Project/OpenROAD/releases/tag/26Q4)
resolves to `c4d317e4fa2398b9880920a1411c20258a2175a9`.
The official `openroad/ubuntu26.04` image is pinned by index digest
`sha256:c3185708e2f1cdb4fed9fb4d84d2882d36a1f1f6af90959ceb07dcb7416fe49d`;
its executable reports `26Q3-2927-gc4d317e4fa`. The development image is pinned
by digest `sha256:a971c4db78c9a4a8db18a9fe136c9731c613e4582a5093180bc7c07e24351e09`.

The source archive's `src/rsz/src/Resizer.tcl` SHA-256 is
`8f72ff3a40bf361df9eee1d4a6ecf163285ebabca3d49c0f8eb958810f65a590`,
verified both against upstream source and the image's source tree. OpenSTA moves
to `e983e15b2cb346badf8f23725fd3914d25312c44`; the other four recursive
submodule revisions remain unchanged, as verified against upstream Git trees.

Reviewing the old/new Resizer Tcl shows additive `repair_design -reroute`,
`repair_timing -skip_buffer_to_inverters`, and `-skip_crpr` options, plus
restoration of command-entry CRPR state after timing repair. Booley's generated
`remove_buffers`, `repair_design`, `repair_timing -setup -skip_gate_cloning`,
`-hold`, `-setup_margin`, and `-repair_tns` calls remain supported. No generated
script changes are needed. Placement, placement RC estimation, area, and timing
reporting are exercised by the physical runs below.

The first full base build rejected the new binary because
`libxcb-cursor.so.0` was absent. Upstream `ldd` and `dpkg-query` identified
`libxcb-cursor0` as the required package; it is now installed in the runtime
stage. The version gate and offscreen GUI smoke verify this runtime closure.

baseline; the historical result was not reproduced with today's mapping inputs.
Only the +16 µm² A/B difference can be attributed to the OpenROAD upgrade.

## Reproduction

Build the exact runtime base from the branch:

```bash
docker build -f src/booley/data/docker/Dockerfile.base \
  -t booley-1064-runtime-base:local .
```

Use `.github/scripts/verify_openroad_runtime.sh /opt/pdk /evidence` in that
image, with this checkout mounted read-only at `/booley-source`, the pinned
Nangate45 PDK at `/opt/pdk`, and a writable evidence directory at `/evidence`.
The PDK can be provisioned with `booley.harness.nangate_pdk.fetch`, as in CI.

For the QoR comparison, download the pinned public RTL into a writable directory
mounted at `/qor`, and run this Python preparation with `PYTHONPATH=/booley-source/src`
in a Booley runtime base containing the pinned Yosys:

```python
from pathlib import Path

from booley.flows.synth.backends.openroad.timing import OpenRoadPdk, write_openroad_script
from booley.flows.synth.backends.yosys.core import _build_yosys_script
from booley.flows.synth.timing import StaTimingConfig

work = Path("/qor")
liberty = Path("/opt/pdk/cell/lib/NangateOpenCellLibrary_typical_ccs.lib")
script = _build_yosys_script(
    [work / "picorv32.v"],
    "picorv32",
    liberty,
    work,
    False,
    {"COMPRESSED_ISA": "1", "ENABLE_MUL": "1", "ENABLE_DIV": "1"},
    "balanced",
)
(work / "synth.ys").write_text("\n".join(script.split("; ")) + "\n")
sdc = work / "clock.sdc"
sdc.write_text("create_clock -name clk -period 10.0 [get_ports clk]\n")
pdk_root = Path("/opt/pdk/nangate45")
pdk = OpenRoadPdk(
    pdk_root / "Nangate45_tech.lef",
    pdk_root / "Nangate45_stdcell.lef",
    pdk_root / "Nangate45.rc",
)
for label in ("old", "new"):
    run = work / label
    (run / "reports").mkdir(parents=True, exist_ok=True)
    write_openroad_script(
        "picorv32",
        liberty,
        work / "sta_picorv32.v",
        (sdc,),
        pdk,
        run / "reports",
        run,
        StaTimingConfig(mode="physical", utilization_pct=50, placement_density=0.8),
        target="synth_core",
        source_sdc_paths=(sdc,),
    )
```

Run `yosys -Q -s /qor/synth.ys` once. Run `openroad -exit run_openroad.tcl`
in `/qor/old` using binary `26Q2-2580-ga9147cf3ae`, then in `/qor/new` using
binary `26Q3-2927-gc4d317e4fa`. In the upstream images the executable is
`/OpenROAD/build/bin/openroad`. Use the same mounts for both runs and retain
stdout, generated scripts, and `reports/`.
