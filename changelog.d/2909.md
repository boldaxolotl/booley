- A Simulation invocation directory written by an older Booley is now reported as no
  longer supported, naming the directory to delete and telling you to start a fresh run.
  Pruning a 0.3.0 coverage run no longer reports an invalid Coverage Campaign, and Goal
  status and the Dashboard no longer say it cannot be read.
- **Breaking change:** Simulation now names everything it stores, reports and accepts for
  the Simulation Record and the Coverage Record, not the Campaign (old name, then new name).
  No old name is accepted as an alias. Records written by Booley 0.4.0 and earlier are
  refused as written by an older Booley, by resume, retention and pruning, the Pre-Sim scan,
  Coverage analysis, `booley coverage`, Goal status, the Dashboard and Goal generated inputs;
  the message names the invocation directory to delete. Report listing and the Dashboard
  show a 0.4.0 Simulation report as written by an older Booley instead of a result.
  Finish or discard any interrupted Simulation run before you upgrade.
  - Directories: `targets/<Target>/campaign/` is now `targets/<Target>/record/` (the
    manifest you pass to `booley flow sim --resume-from` is now `record/manifest.json`), and
    each attempt's `coverage-campaign/` is now `coverage-record/`.
  - Simulation Record: the identity key `campaign_id` is now `simulation_record_id` in the
    manifest (`booley.simulation-campaign-manifest/v4` is now
    `booley.simulation-record-manifest/v1`), each attempt result
    (`booley.simulation-result/v3` is now `v4`), the dependency receipt
    (`booley.simulation-campaign-dependency/v1` is now `booley.simulation-record-dependency/v1`),
    the manifest's `prerequisites[]` entries, the attempt, build attempt, build result,
    simulator bundle, executable snapshot and Pre-Sim evidence records (schemas `v1` to `v2`)
    and the run-directory marker. The supervised child context is now
    `booley.supervised-child-context/v2`, and a child lane's terminal causes `campaign_error`
    and `campaign_cancelled` are now `record_error` and `record_cancelled`. Cleanup still
    releases a child lane a killed Booley 0.4.0 left behind.
  - Summary, transport and projection: `booley.simulation-campaign-summary/v1` is now
    `booley.simulation-record-summary/v1` with `simulation_record_id`;
    `booley.cocotb-campaign-transport/v1` is now `booley.cocotb-record-transport/v1`; the
    projection `targets/<Target>/simulation.json` moves from `booley.simulation-projection/v3`
    to `v4`, where `campaign_id`, `campaign_manifest` and `coverage_campaign` are now
    `simulation_record_id`, `simulation_record_manifest` and `coverage_record`. The evidence
    kinds `simulation_campaign_manifest` and `coverage_campaign_reference` are now
    `simulation_record_manifest` and `coverage_record_reference`, in the projection, in the
    artifact references of a `report.json` and in a manifest's `prerequisites[].manifest`.
  - Coverage Record: `booley.coverage-campaign/v5` is now `booley.coverage-record/v1` with
    `coverage_record_id` in place of `campaign_id`; the point store moves from
    `booley.coverage-points/v1` to `v2` (header key `coverage_record_id`). The Target
    `coverage.json` reference `booley.coverage-campaign-reference/v1` is now
    `booley.coverage-record-reference/v1`: `simulation_campaign_id` is now
    `simulation_record_id`, the nested `coverage_campaign` object is now `coverage_record`
    with `coverage_record_id`, and the evidence kind `coverage_campaign_manifest` is now
    `coverage_record_manifest`. The availability record that native pruning leaves moves from
    `booley.coverage-availability/v1` to `v2` with `coverage_record_id` and
    `coverage_record_sha256` in place of `campaign_id` and `campaign_sha256`.
  - `coverage_analyst` report: `booley.coverage-analysis/v1` is now `v3` and `v2` is now `v4`;
    `campaign_id` is now `coverage_record_id`, `campaign_reference` is now
    `coverage_record_reference`, `observed_evidence.campaign_manifest` is now
    `observed_evidence.coverage_record_manifest`, the category `cp1_not_in_campaign` is now
    `cp1_not_in_record`, and the in-memory record `booley.coverage-campaign/v1` is now
    `booley.coverage-record-document/v1`. The `coverage_evidence` tool overview names
    `coverage_record_id` instead of `campaign_id`.
  - `coverage_analyst` input: the `--campaign` argument and the MCP parameter `campaign` are
    now `--record` and `record`, and the environment variable `BOOLEY_COVERAGE_CAMPAIGN` is
    now `BOOLEY_COVERAGE_RECORD`. Its scratch directories are now `booley-coverage-record-*`
    (leftover `booley-coverage-campaign-*` directories are still cleaned up).
  - Simulation report and Flow output (`report.json`, `progress.json`, MCP and Dashboard):
    `detail.campaigns` is now `detail.records`, `detail.campaign_integrity_error` is now
    `detail.record_integrity_error` and the dry-run `detail.campaign_preview` is now
    `detail.record_preview`. Each Target row in them names `simulation_record_id` instead of
    `campaign_id`, and its `dependency` value `local_campaign` is now `local_record` and
    `external_origin_campaign` is now `external_origin_record`. A Target row's
    `coverage_campaign` is now `coverage_record`, on passing and failed Targets. The
    `campaign_path` fact is now labelled "Coverage Record path". The report schema
    `booley.simulation-report/v3` is unchanged; a report with `detail.campaigns` is an
    older one.
  - Configuration: the `[flows.sim] run_cwd` placeholder `{campaign}` is now `{record}`; a
    configuration that still uses `{campaign}` fails with a message naming `{record}`.
