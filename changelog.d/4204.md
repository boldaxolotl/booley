- The remaining Sandbox repair messages now name the steps that
  [Applying Sandbox changes](https://booley.dev/docs/sandbox/#applying-sandbox-changes)
  documents for how you open the Sandbox, instead of one workflow for every
  Sandbox. That covers the externally managed image refusal of
  `booley session refresh`, the Simulation Flow compiler-cache, Verilator
  coverage and cocotb import hints, the missing EDA binary check, the Doctor
  probe failures that cannot enter the Sandbox, the stored-credential notice,
  and the Sandbox git identity override. Inside the Sandbox, where the owner
  is unknown, they name both the VS Code and the headless steps. The
  licensed-relay repair tells a VS Code owner to remove its container before
  `booley session down`, and `handles.map-size` names the smallest restart for
  each owner: stop and reopen the Sandbox in VS Code, or `docker stop` and
  `booley session up` when headless. A missing EDA binary says plain
  `booley init`, not `booley init --force`.
  ([issue #4204](https://github.com/boldaxolotl/booley/issues/4204))
