- **Breaking change:** a Simulation run now names its summary, cocotb transport and
  Simulation projection for the Simulation Record. The summary schema
  `booley.simulation-campaign-summary/v1` is now `booley.simulation-record-summary/v1`
  and its `campaign_id` key is now `simulation_record_id`. The cocotb transport schema
  `booley.cocotb-campaign-transport/v1` is now `booley.cocotb-record-transport/v1`. The
  Simulation projection `targets/<Target>/simulation.json` moves from
  `booley.simulation-projection/v3` to `v4`: `campaign_id`, `campaign_manifest` and
  `coverage_campaign` are now `simulation_record_id`, `simulation_record_manifest` and
  `coverage_record`. The evidence kinds `simulation_campaign_manifest` and
  `coverage_campaign_reference` in the projection and in the artifact references of an
  invocation's `report.json` are now `simulation_record_manifest` and
  `coverage_record_reference`. No old key, schema or evidence kind is accepted.
  Simulation records written by Booley 0.4.0 and earlier are refused as written by an
  older Booley, by retention and pruning, and by Coverage analysis; the message names the
  invocation directory to delete. Pruning also refuses while an older run's projection
  or resume receipt stays in the same report root, until you delete that directory.
  Finish or discard any interrupted Simulation run before you upgrade.
