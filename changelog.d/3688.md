- **Breaking change:** a Simulation run with `--coverage` now names its Coverage Record
  formats for the Coverage Record. The stored record, schema `booley.coverage-campaign/v5`,
  is now `booley.coverage-record/v1`, and its `campaign_id` key is now `coverage_record_id`.
  The record's point store moves from `booley.coverage-points/v1` to `v2`, and its header
  and the manifest's `point_store` document use the same key. The Target `coverage.json`
  reference, `booley.coverage-campaign-reference/v1`, is now `booley.coverage-record-reference/v1`:
  `simulation_campaign_id` is now `simulation_record_id`, the nested `coverage_campaign`
  object is now `coverage_record` with `campaign_id` now `coverage_record_id`, and the evidence
  kind `coverage_campaign_manifest` in a Simulation result is now `coverage_record_manifest`.
  The availability record that native pruning leaves, `booley.coverage-availability/v1`, is
  now `v2` with `coverage_record_id` and `coverage_record_sha256` in place of `campaign_id`
  and `campaign_sha256`. The `coverage_analyst` report moves from `booley.coverage-analysis/v1`
  to `v3` and from `v2` to `v4`; its `campaign_id` is now `coverage_record_id`, its
  `campaign_reference` input is now `coverage_record_reference`, `observed_evidence.campaign_manifest`
  is now `observed_evidence.coverage_record_manifest`, and the reference category
  `cp1_not_in_campaign` is now `cp1_not_in_record`. The overview of the `coverage_evidence`
  tool names the record `coverage_record_id` instead of `campaign_id`. No old key, schema,
  evidence kind or category is accepted. Coverage Records and references written by Booley
  0.4.0 and earlier are refused as written by an older Booley, by Coverage analysis,
  `booley coverage` and retention; the message names the invocation directory to delete.
  Finish or discard any interrupted Simulation run before you upgrade.
