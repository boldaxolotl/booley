- Breaking: memory admission is now how Booley admits every simulation,
  synthesis, FPGA implementation, lint, and Custom Flow Job. A Job reserves its
  estimated peak memory and runs while the reservations fit the Memory Budget
  (`[jobs].memory_budget`, else the container's memory limit, else the
  installed memory). Specialists keep `max_light` and `queue_max`. Parallel
  simulation tests run while their reservations fit, and a Job killed out of
  memory runs once more, alone.
- `max_heavy` and `heavy_memory` in `[jobs]` are retired. While `booley.toml`
  sets either, Flow and Specialist runs and every command that works on a Project
  refuse and name each key and its line; `booley doctor` and `booley upgrade` still run. `booley doctor` reports a FAIL
  instead of crashing. Delete the lines, or run `booley-heal` to remove them.
- A Project that uses Vivado now needs a Seat Cap: add
  `[jobs.seats]` with `vivado = <seats>` to `booley.toml`. Without it,
  `booley doctor` fails and the Flow is refused.
- `booley doctor` no longer checks slot capacity, and `booley doctor --deep` no
  longer calibrates `heavy_memory`. It warns when `[sandbox].memory` is unset,
  because the Memory Budget then falls back to installed memory.
  ([issue #3247](https://github.com/boldaxolotl/booley/issues/3247))
