- A queued Job's wait text now names what holds it. The CLI `[admission]` line reads
  `queued (position N): ...` and leads with the actual cause: waiting in queue order behind a
  named Job, waiting for a tool's seat (held of cap), or waiting to run alone after an
  out-of-memory kill. Only a Job that needs more memory than is free reports its need, the
  free memory and the largest holders. At a holder's release, free memory and position count
  the Jobs ahead that start now. The MCP poll and handoff and the Dashboard "Queue" row show
  the same text.
  ([issue #4540](https://github.com/boldaxolotl/booley/issues/4540))
